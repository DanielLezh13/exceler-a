# Exceler A Project Rules

- Preserve curriculum continuity: questions may use only current or previously taught material.
- Never introduce future syntax, methods, terminology, behavior, or programming patterns inside required practice.
- Practice should build mastery through controlled structural variation, repetition, retrieval, and cumulative application—not superficial format variety.
- Prefer concrete Java behavior over definition recall whenever the concept can be demonstrated in code.
- Reuse earlier concepts naturally in later problems.
- Difficulty should come from interacting known rules, tracing, debugging, choosing an approach, and reduced scaffolding—not confusing wording or obscure trivia.
- Do not treat code comprehension as equivalent to code production. Substantial units must eventually test independent construction from behavioral requirements and a blank editor.
- Apply code production throughout practice, including basic sections: when a concept is meaningfully expressed in Java, give the learner repeated opportunities to retrieve and write it near where it is taught. Choose the format and amount by the skill, not a coding-question quota; preserve useful recognition, tracing, debugging, and conceptual work.
- In later production practice, present a concrete problem with fixed facts and required results; do not disguise a line-by-line Java recipe with themed nouns. Let the learner discover the variables, intermediate state, operations, and program structure.
- Preserve strong existing questions; do not regenerate everything blindly.
- Question validators must match the visible prompt and accept valid equivalent solutions when the prompt allows implementation choice.
- Keep every question self-contained: when a prompt refers to this code, declaration, line, program, output, or an example shown elsewhere, display the referenced material inside that question.
- Do not redesign unrelated UI or architecture during curriculum work.
- After course-content changes, run continuity checks and relevant tests.
- Before editing, adding, moving, auditing, or generating curriculum, lessons, questions, reviews, mastery tests, or assessments, read `docs/PRACTICE_AUTHORING.md` completely and follow it.
